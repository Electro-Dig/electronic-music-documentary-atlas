# 纪录片资料核验与清洗方法

本方法用于把 Obsidian 资料整理成可公开展示的网站数据。目标不是把所有网络线索都收进去，而是让每部片目的公开信息可追溯、可解释、不过度承诺。

## 1. 确定批次范围

- 优先按网站公开路线处理：入门路径、机器与录音室、舞池与城市、欧洲线索、女性先锋。
- 每批只处理路线中的主片目；辅助片目如果已在前一批清洗过，不重复计入。
- 如果某片与电子音乐主题关系较弱，先降为相关议题或延伸片目，不强行保留在重要片库。

## 2. 建立事实字段

每部片至少核对这些字段：

- 片名：原名优先；中文名只保留成熟译名。
- 年份、片长、导演或制作方。
- 简介：120-180 字中文，说明影片对象、历史位置和为什么值得进入片库。
- 观看渠道：只记录可核验的平台、机构或馆藏，不把搜索结果当渠道。
- 来源：每部至少保留一个相对可靠来源。

## 3. 来源优先级

从高到低：

1. 片方、导演、发行方、电视台、制片机构、官方 Vimeo/YouTube 页面。
2. 电影节、博物馆、大学、公共媒体、图书馆馆藏。
3. 正规流媒体平台和聚合平台。
4. IMDb、TMDb、Wikipedia、粉丝维基等数据库，只能辅助校对，不单独支撑关键判断。
5. B站、YouTube 用户上传只作为“可观看线索”，除非能确认官方或授权来源。

## 4. 观看渠道判断

- `free`：公开可访问的完整观看页，且来源相对可靠。
- `library`：图书馆、Kanopy、Alexander Street 等馆藏或教育授权渠道。
- `subscription` / `rental` / `purchase`：明确存在订阅、租赁或购买入口。
- `event_only`：电影节、机构放映、现场活动页。
- 空数组：没有找到稳定、可核验的完整观看渠道。页面显示“暂无稳定观看渠道”。

所有公开放映默认标记 `permission_required`，除非来源明确给出可公开放映授权。

## 5. B站与公开视频处理

- 必须能打开具体视频页，才写入 `watch_channels`。
- 如果只是搜索结果、转载标题或不稳定缓存，不写入正式渠道。
- 用户上传但未能确认授权时，可作为低优先级线索；公开放映仍然保持 `permission_required`。

## 6. 清洗规则

- 删除内部整理痕迹：`正文观看渠道待拆分`、`截图待核验`、`note` 等。
- 不在公开卡片展示策展定位、观看说明、内部备注。
- 不用自动推断时间跨度代替事实年份；时间轴只表示发行年份。
- 对不确定信息用空值或 `unknown`，不编造。

## 7. 验证规则

每批完成后必须跑测试：

- 简介 120-180 字。
- 没有占位渠道和内部备注。
- 不展示已失效或不可确认的免费观看渠道。
- JSON 可解析，页面脚本语法通过。
- 全量测试通过后再进入下一批。
