# 电子音乐纪录片地图开发回顾

日期：2026-05-24

## 1. 项目定位的形成

这个项目最初不是一个普通片单网页，而是从一批 Obsidian 纪录片资料出发，逐步转成一个面向读者的电子音乐纪录片策展网站。项目目标在开发过程中发生过几次重要校正：

- 从“资料整理”转为“公开策展档案”。
- 从“A 类 / S 级”内部分级转为“核心影片 / 重要影片 / 延伸片目”的读者语言。
- 从数据库式筛选转为封面墙、观看路线、标签浏览和影片 dossier。
- 从纯文本信息展示转为带有 Three.js 空间封面墙和实验室入口的网页体验。

最终形成的产品结构是三层：

1. 首页封面墙：用空间化封面展示建立第一印象。
2. 策展路线和片库：帮助读者按线索进入，而不是直接面对数据库。
3. 详情档案和实验室：提供影片简介、观看渠道、来源记录，以及关系探索。

## 2. 开发阶段回顾

### 阶段一：资料盘点与真实性核查

起点是用户在 Obsidian 中整理的电子音乐纪录片资料。第一批任务是认真查看资料是否真实、准确，并为每部纪录片补充更可靠的简介、来源和观看渠道。

关键动作：

- 读取并理解原始资料目录。
- 判断每部纪录片是否真实存在、标题是否准确、年份和导演是否可靠。
- 收集片方、发行方、电视台、电影节、IMDb/TMDb 等来源。
- 区分“可观看线索”和“可公开放映授权”。
- 逐步补充 B站、YouTube、小红书、馆藏、VOD 等渠道。

这一阶段暴露出一个重要问题：纪录片资料很容易因为网络转载、中文译名、用户上传和平台搜索结果而混入不稳定信息。因此后来专门沉淀了 `docs/content-verification-method.md`。

### 阶段二：片单标准和信息结构

项目一开始存在“都纳入”的倾向，但后续明确了主片单不能无限扩张，需要有进入标准。

已确认的标准：

- 优先纳入能解释电子音乐史结构性节点的影片。
- 原名优先；中文名只保留成熟译名，不硬译。
- `How Music Got Free` 这类音乐产业史影片不放入主电子音乐片库，转为相关议题或延伸。
- B 类或边缘片目不进入首页封面墙和主片库。
- 每部影片详情应包含事实信息、120-180 字中文简介、观看渠道和来源。
- 详情卡去掉策展定位、观看说明、内部备注等不适合读者的内容。

这个阶段的产物包括：

- `docs/superpowers/specs/2026-05-21-content-display-design.md`
- `docs/content-verification-method.md`
- `docs/content-batch-02-machine-studio.md`
- `docs/content-batch-03-05-routes.md`
- `docs/content-watch-channels-2026-05-22.md`
- `docs/youtube-audit-2026-05-22.md`

### 阶段三：静态网站原型

第一版网页采用静态 HTML/CSS/JavaScript，从 `data/documentaries.json` 渲染片库。

初期功能包括：

- 首页概览。
- 片库网格。
- 搜索和筛选。
- 详情弹窗。
- 发行年份索引。
- 观看路线。

这个阶段很快暴露出几个问题：

- 页面太像资料表或资源帖。
- 标签乱码和中文编码问题曾在 UI 中暴露。
- 时间轴曾错误地用推断的“内容覆盖时段”展示影片，造成明显幻觉。
- 路线和主题筛选过于机械，容易让一部总览影片在多个路线中重复出现。

这些问题推动项目从“信息展示”转向“策展体验”。

### 阶段四：视觉参考研究与设计方向

用户明确指出页面过于板正、老套，希望参考更现代的策展网页。于是进行了视觉案例研究，并整理到：

- `docs/visual-reference-research-2026-05-22.md`
- `docs/visual-references/screenshots/`

主要参考对象：

- Google Arts & Culture - Music Makers & Machines
- Ishkur's Guide to Electronic Music
- Every Noise at Once
- Radiooooo
- The Pudding - Music DNA
- The Public Domain Review - Collections

得到的关键判断：

- 首页应该像“影像展览”，不是表单入口。
- 封面墙是当前项目最强的视觉资产，应放在第一屏。
- 路线区应像策展章节，而不是分类卡片。
- 片库仍然需要可靠检索，但应该退到第二层。
- Three.js 交互适合作为“空间封面墙”和“实验室”，不应强行替代全部信息结构。

### 阶段五：交互原型迭代

围绕 React + Three.js 和封面墙，开发了几个方向：

- 节点关系图。
- 封面卡片进入三维空间。
- Patch cable / graph lab 实验室。
- Spatial film wall 首页封面墙。
- 发行年份索引的降级版本。

用户反馈推动了关键修正：

- 不要用抽象节点替代纪录片封面，影片展示应以封面为第一视觉。
- 时间轴只能表示发行年份，不能编造影片覆盖年代。
- 封面墙交互需要更流畅，点击应有浮窗或档案入口。
- 首页封面墙之外的区域不应拦截鼠标滚轮。
- 深色主题不适合整体；纸张和玻璃墙面风格也不合适，最后转向浅色、纯色块、信号色点缀。

### 阶段六：公共呈现层和测试

为了避免直接破坏源数据，项目加入了 `assets/presentation-data.js` 作为公开呈现层。

它解决的问题：

- 内部分级转成公开标签。
- 原名优先，成熟中文名作为副标题。
- 主片库、延伸片目、相关议题分离。
- 人工策展路线，避免关键词自动匹配造成重复。
- 公开标签数量限制，避免卡片信息过载。

同时建立了 Node 测试：

- `tests/presentation-data.test.mjs`
- `tests/app-rendering.test.mjs`
- `tests/app-filtering.test.mjs`
- `tests/app-routes.test.mjs`
- `tests/film-wall-data.test.mjs`
- `tests/film-wall-page.test.mjs`
- `tests/timeline-data.test.mjs`
- `tests/timeline-view.test.mjs`
- `tests/content-quality.test.mjs`

这些测试在后续迭代中非常关键，尤其用于防止：

- 内部 `A/S/B` 语言重新出现在公共 UI。
- `How Music Got Free` 回到主片库。
- 时间轴再次出现推断跨度。
- 详情弹窗重新出现内部备注。
- tag 和路线重复膨胀。

### 阶段七：内容补充与观看渠道

用户提供了大量经过人工确认的 B站、小红书、YouTube 链接，并指出之前 YouTube 搜索不够充分。项目随后补充了多部重要影片和渠道：

- The Rise of the Synths
- Break_The_Wall
- Sound of Berlin
- The Untold History of Disco

同时更新了若干已有影片的 B站、小红书、YouTube 渠道，并用 `source_kind`、`subtitle`、`access_type`、`public_screening` 等字段标记来源状态。

这个阶段的经验是：观看渠道不是简单 URL 列表，而应该是一组带来源性质的证据。尤其用户上传、熟肉、生肉、官方上传、平台馆藏都要区分。

### 阶段八：中英文切换与发布

发布前补充了界面中英文切换：

- 默认中文。
- 通过 `data-i18n` 管理静态文案。
- 通过 `UI_STRINGS` 管理动态文案。
- 动态渲染的筛选、路线、弹窗、片源标签也接入翻译。

同时整理了简要双语 README，新增 `.nojekyll`，推送公开 GitHub 仓库，并部署到 GitHub Pages 和 Netlify。

发布地址：

- GitHub 仓库：https://github.com/Electro-Dig/electronic-music-documentary-atlas
- GitHub Pages：https://electro-dig.github.io/electronic-music-documentary-atlas/
- Netlify：https://emda-documentary-atlas.netlify.app/

## 3. 关键决策

### 不把片库做成“评分站”

网站不是影迷评分站，也不是资源聚合站，而是电子音乐历史的策展入口。因此主维度不是分数，而是影片在电子音乐史中的解释力。

### 不自动推断历史跨度

曾经的时间轴把影片主题误读为历史覆盖时段，例如把一部纪录片展示成 1950-2029 之类的长条，这是明显幻觉。最终规则是：时间索引只显示发行年份。

### 不让标签系统吞掉策展判断

早期标签太多，且主题路线重复过度。最后采用“路线 + 少量公开标签 + 搜索”的结构，并让路线成员由人工定义。

### 视觉上以封面为核心

电子音乐纪录片网站最直接的视觉资产就是影片封面。抽象节点、纯文本和统计卡都不能替代封面，因此首页改为封面墙。

### 资料来源和观看渠道分开

资料来源用于支撑影片事实和简介；观看渠道用于告诉读者哪里能看。两者不能混用。B站和 YouTube 用户上传可以作为观看线索，但不能等同授权。

## 4. 做得有效的部分

- 先研究资料和内容标准，再做公开呈现层，减少了后期返工。
- 使用 `presentation-data.js` 保护源数据，把公共展示逻辑放在可测试的中间层。
- 用测试锁定用户反复强调的原则，避免 UI 回退到内部数据库状态。
- 视觉研究文档帮助项目摆脱当前页面惯性，而不是只在旧设计上微调。
- 封面墙、片库、路线、实验室分层后，网站目标更清晰。
- 发布流程最终稳定：GitHub public + Pages + Netlify。

## 5. 仍然薄弱的部分

- 影片简介虽然已经批量清洗，但仍需要继续逐部核验专业来源。
- YouTube 搜索和 B站渠道核验最好脚本化，否则容易漏。
- 英文界面目前主要是 UI 层翻译，影片内容仍以中文读者为主。
- 移动端可用性还需要更多真实设备检查。
- Three.js 实验室仍是附加入口，如何与主片库形成更有意义的关系仍可继续探索。
- 视觉系统已经脱离纸张和玻璃墙感，但还可以继续强化“电子音乐 / 信号 / 影像档案”的统一语言。

## 6. 可复用经验

这个项目的核心经验不是“做一个片库网页”，而是一套把粗糙研究资料转为公开策展网站的方法：

1. 先做事实核验，不急着做视觉。
2. 明确片单标准，不把所有相关内容都塞进主目录。
3. 把内部整理语言翻译成读者语言。
4. 用视觉案例研究打破现有界面惯性。
5. 建立呈现层，避免源数据和 UI 逻辑纠缠。
6. 用测试锁定策展规则、内容边界和交互约束。
7. 发布前做 README、部署和链接校验。
